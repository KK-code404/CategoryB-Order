# 核销看板

入口：侧栏「业务驾驶舱」→「核销看板」。看板只读取正式核销台账，不改变既有风险雷达、发货沙盘或业务简报。

## 使用

1. 通过顶部快捷日期切换「8.27—9.3」「本月」「近 30 天」或「8 月」，无需填写查询表单。
2. 代理商和计量单位使用按钮切换；不同单位始终独立统计，不做跨单位合计。
3. 看板由六组图形组成：每日发货柱状图、订单池余额趋势、订单状态环形图、代理商发货占比、订单余额 TOP 6、代理商核销结构。
4. 柱状图支持键盘聚焦或点击日期，并在图下给出当日精确数量。需要逐笔核对时，使用「查看订单台账」或「查看发货明细」进入既有业务页面。
5. 「全屏展示」适合会议大屏；按 Esc 或点击「退出全屏」返回。不支持全屏 API 的浏览器会提示使用 F11。

## 正式数据口径

- 仅已进入核销流水的数量纳入图表，按原申请发货日期汇总；冲销抵减原日期，不使用邮件接收日期。
- 核销数量不等于物流实际发运、到货或签收。图表零值仅表示没有已入账的净变化，不能证明未发生线下业务。
- 期初剩余 − 区间净核销量 = 期末剩余。余额曲线是现有订单池的回溯结果，不是历史时点库存快照；不还原订单新增、修改的历史。
- 未分日历史核销量保留在余额内，不捏造日期，并在页面提示有此类订单行。
- 同代理商 + 订单号为一单；零件为订单行。筛选某单位时，订单数和各图只覆盖该单位的可见订单行。
- 服务端强制代理商范围，分析返回不含邮箱、电话、地址或收货人。

## 技术边界

- 只读接口：`GET /api/orders/reconciliation-analytics?start=YYYY-MM-DD&end=YYYY-MM-DD`，沿用登录 Cookie 和角色权限。
- 批次入账仅允许部署期管理员脚本调用，不提供公开 HTTP 写入接口。
- 无新增依赖、数据库表或迁移；前端图表均为 Vue 3 组件与原生 SVG/CSS。
- 工作簿、导入快照和批次证据保存在私有运行存储中，不提交到代码仓库。

## 验证

后端测试覆盖范围校验、代理商隔离、正负流水、批次证据一致性、余额不足全量回滚、重复执行幂等、无邮件副作用和补录冲销。前端测试覆盖六图看板、筛选、键盘交互、空态、错误重试、迟到响应和多单位隔离。浏览器实机视觉检查仍需在可用浏览器连接中执行。
